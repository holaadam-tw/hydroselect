## Context

HydroSelect 目前是單檔架構（`src/App.js`），所有邏輯集中在一個檔案中，包含常數定義、計算引擎 `calcSystem()`、品牌資料 `BRANDS`、樣式和 UI 元件。計算結果回傳規格數值（缸徑、排量、功率、閥件通徑等），品牌推薦僅顯示系列名稱和文字說明。

現在需要在計算結果與品牌推薦之間新增一層「型號匹配」邏輯，並新增 PDF 報價單生成功能。客戶對象為終端工廠和油壓系統商。

## Goals / Non-Goals

**Goals:**
- 計算結果自動對應各品牌具體產品型號（含型號字串、規格參數）
- Propiston 品牌可生成正式報價單 PDF（含公司抬頭、產品明細）
- 其他品牌可匯出「建議規格書」（無價格資訊）
- 維持前端純靜態架構，不引入後端

**Non-Goals:**
- 多語系支援（第二期）
- 客戶帳號系統（第二期）
- 技術工具書生成（第二期）
- 即時庫存或價格 API 串接
- 購物車 / 線上下單功能

## Decisions

### 1. 產品資料結構：獨立資料模組 vs 內嵌常數

**決定**：將產品型錄資料抽取為獨立模組 `src/data/productCatalog.js`，不再塞進 App.js。

**理由**：
- 產品型錄資料量大（每品牌多系列、每系列多型號），放在 App.js 會導致檔案膨脹到難以維護
- 獨立模組便於未來改為 API 取得或從 Excel/CSV 匯入
- 替代方案：維持 App.js 內嵌 → 放棄，檔案會超過 2000 行

**資料結構設計**：
```js
// src/data/productCatalog.js
export const PRODUCT_CATALOG = {
  pump: {
    propiston: [
      { series: "P", models: [
        { model: "P16V-RS-11-CC-10-J", displacement: 16, maxPressure: 35, type: "piston" },
        { model: "P22V-RS-11-CC-10-J", displacement: 22, maxPressure: 35, type: "piston" },
        // ...
      ]},
    ],
    yuken: [...],
    rexroth: [...],
    parker: [...],
  },
  valve: { /* 方向閥、溢流閥 */ },
  cylinder: { /* 油壓缸 */ },
  motor: { /* 電機 */ },
};
```

### 2. 型號匹配邏輯：規格向上取整匹配

**決定**：對每個品牌，找到「規格 ≥ 計算需求」的最小型號，與現有 `roundUp()` 策略一致。

**理由**：液壓元件選型永遠向上取整（安全裕度），這是行業標準做法。

### 3. PDF 生成方案：jsPDF + jspdf-autotable

**決定**：使用 jsPDF（輕量前端 PDF 生成）搭配 jspdf-autotable（表格排版外掛）。

**理由**：
- 純前端，不需要後端服務
- jsPDF 是最成熟的前端 PDF 方案，生態完善
- jspdf-autotable 專門處理表格排版，適合報價單格式
- 替代方案：react-pdf → 偏向 PDF 檢視器，生成能力較弱；html2pdf → 依賴 html2canvas 截圖品質不穩定
- 中文字型：需內嵌 Noto Sans TC 字型子集（約 1-2MB），否則中文會亂碼

### 4. 報價單 vs 建議規格書的差異化

**決定**：
- Propiston 品牌：完整報價單（公司抬頭、報價日期、有效期、產品明細含單價、合計金額）
- 其他品牌：建議規格書（僅列型號與規格參數，無價格，無公司抬頭，標注「此為建議規格，非正式報價」）

**理由**：Propiston（大正）是平台營運方自有品牌，只有自有品牌才應出正式報價。其他品牌的價格會隨通路、數量、時間變動，不宜由平台定價。

### 5. 程式碼組織：漸進式拆分

**決定**：新增以下檔案，但不大規模重構現有 App.js：
- `src/data/productCatalog.js` — 產品型錄資料
- `src/utils/productMatcher.js` — 型號匹配邏輯
- `src/utils/pdfGenerator.js` — PDF 報價單 / 規格書生成
- `src/components/ProductMatchResult.js` — 型號匹配結果 UI 元件

**理由**：避免大規模重構風險，新功能用新檔案，舊功能維持原樣。App.js 只需新增 import 和少量整合程式碼。

### 6. UI 設計規範：淺色工業專業風

**決定**：全面改為淺色/白底專業工業風格，取代現有暗黑主題。視覺參考 Bosch Rexroth 官網的乾淨、信任感、工程專業調性。

**色彩系統**：
- 主色調：深藍 `#003366`（工業信任感，用於標題、導航、重要元素）
- 品牌強調色：橙色 `#FF6600`（Propiston 品牌色，用於 CTA 按鈕、重點標示、活躍狀態）
- 背景色：白色 `#FFFFFF`（頁面背景）
- 卡片背景：淺灰 `#F8F9FA`
- 卡片邊框：`#E2E8F0`
- 主文字：`#1A1A1A`
- 副文字/說明：`#666666`
- 成功/數值：`#059669`（綠色，用於計算結果正面指標）
- 警告/超出範圍：`#DC2626`（紅色）

**版面佈局**：
- 頂部 Header：白底 + 底部淺灰分隔線，左側 Propiston Logo 區域（深藍底色 + 橙色點綴，強化品牌辨識度），右側副標題「液壓系統智能選型平台」
- 最大寬度維持 1000px 居中，兩側留白
- 卡片圓角 8px，淺灰底色 + 1px 邊框，無重陰影（乾淨感）
- 分頁（Tab）用深藍底色標示活躍狀態，橙色下方指示線

**表格設計**：
- 表頭：深藍 `#003366` 底色 + 白字
- 交替行：奇數行白色、偶數行 `#F8F9FA`
- 邊框：`#E2E8F0` 細線
- 單元格 padding 充足，確保好讀

**計算結果數據展示**：
- 關鍵數值用大字體（24-28px）+ 粗體
- 數值下方小字標示單位（如 mm、cc/rev、kW）
- 數值卡片用白底 + 左側深藍色條做視覺引導

**報價單按鈕**：
- Propiston「生成報價單」：橙色 `#FF6600` 實心按鈕，白字，大尺寸，放在品牌卡片最醒目位置
- 其他品牌「匯出建議規格」：深藍外框按鈕（outline style），視覺層級較低
- hover 效果：微微加深底色 + 輕微上移陰影

**響應式設計**：
- 桌面（≥768px）：雙欄/多欄 Grid 佈局
- 手機（<768px）：單欄堆疊，觸控友善（按鈕最小高度 44px，間距加大）
- 輸入表單在手機上全寬顯示
- 結果表格在手機上水平可滾動

**理由**：
- 暗黑主題適合開發者工具，但液壓產業客戶（工廠主管、系統商業務）更習慣專業白底介面
- 深藍+橙色組合在工業品牌中極為普遍（Rexroth、Parker、Eaton 等），能快速建立信任感
- 響應式設計確保工廠現場人員可用手機操作

## Risks / Trade-offs

- **中文字型體積** → jsPDF 需內嵌中文字型（~1-2MB），會增加 bundle 大小。緩解：使用字型子集化工具只嵌入常用字；或使用 dynamic import 延遲載入 PDF 模組。
- **產品資料維護** → 硬編碼的型錄資料會過時。緩解：資料結構設計清晰，未來可改為從 API/CSV 載入；第一期先以靜態資料起步。
- **價格敏感性** → Propiston 報價單含單價，若被競爭對手取得可能有商業風險。緩解：報價單僅在使用者主動點擊「生成報價單」時產生，且 PDF 標註「僅供參考」。
- **型號匹配準確度** → 簡單的「向上取整」可能不適用所有情境（如特殊安裝方式、環境條件）。緩解：UI 標註「建議規格，實際選型請洽業務確認」。
